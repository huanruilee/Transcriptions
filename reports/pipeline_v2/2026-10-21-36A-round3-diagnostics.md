# 36A 第三輪：漏辨診斷、分段與中文 ASR 對照

## 結論

完成 39 組有效 GPU ASR 結果及 9 組接回現行校對流程的候選；另保留 1 次診斷工具失敗及重跑證據。**本輪尚未達成較原流水線 CER 下降 40%，不更換正式預設、不合併或發布候選。**

最有價值的發現是：長段缺漏可以藉完整音訊分段改善，但每段重複注入底本提示可能造成提示詞回聲與異常重複。兩者需要一起評估。Qwen3-ASR 已在 GB10 實跑，可作第二辨識器候選，尚無整體勝出證據。

所有實驗檔案存於 `tmp/pipeline_v2/36A/round3/`；八個已發布 36A／36B 檔案與先前保護雜湊相同。既有 Whisper 8010 與 LLM 8001 持續運作，未重啟、替換或安裝套件到其環境。

## 方法與新增工具

- 先寫失敗測試，再實作七項 Python 行為合約，涵蓋刪除錯誤、重複保留、時間區間聯集、空白輸出、無效時間、單因子參數、完整分段與文字風險旗標。
- `scripts/lib/asr_diagnostics.py`：CER 的替換／刪除／插入分解；獨立執行語音活動檢查後計算未覆蓋時間；完整音訊分段；提示詞回聲、重複短語、替代字元與字幕雜訊的待聽核旗標。**旗標不自動刪字。**
- `scripts/benchmark_whisper_isolated.py`：保留原參數作控制組，單獨改重複懲罰、VAD、詞級時間或溫度重試。增加解碼診斷、完整分段與提示詞開關；無效時間保留原始結果，不夾限成看似有效的時間戳。
- `scripts/benchmark_qwen_asr_isolated.py`：使用本機完整 HF 權重，以原生 Transformers／CUDA 推論，保存權重及音訊雜湊。沒有遠端音訊上傳。
- `scripts/evaluate_asr_diagnostics.py`：檢查音訊雜湊、時長與已發布樣本，分開報告原始辨識及校對後 CER；輸出可供標註工具匯入的任務 JSON。校對前檢查 LLM 連線，避免把網路失敗時保留原文的結果算成成功校對。

語音活動檢查使用 faster-whisper 內附 Silero 的另一次執行，500ms 靜音、零 padding。它與辨識使用的 VAD 不是不同模型，不能當成人工音訊真值。詞級覆蓋與句級覆蓋也不能直接排名；高時間覆蓋不代表文字正確。

## 實驗設計

沿用固定三段音檔、已發布參考稿及正規化規則；總參考字數 1,295。舊版基準為 `44a23af22c4dc504cc40fbe78b9a5c28ea1e7b96`，沿用第二輪已記錄的校對後結果及雜湊，沒有重新挑選較差基準。

兩個 Whisper 模型各跑三段、五組單因子對照：控制組、重複懲罰改 1.0、關閉 VAD、關閉詞級時間、啟用溫度重試，共 30 組。large-v3 再各跑三段的完整分段，以及相同分段取消提示詞，共 6 組；Qwen3-ASR 跑三段，共 3 組。原先關閉詞級時間的一組因超出音訊範圍的時間戳導致診斷失敗，修正證據保存方式後重跑；原失敗檔案及 stderr 仍保留。

分段優先選 15–25 秒內的靜音中點，沒有合適中點時切在 20 秒；保留所有靜音與音訊樣本，無重疊、無文字去重。連續語音仍可能在切點斷詞；本輪未實作重疊與聲學對齊合併。

Whisper 控制參數為 int8、beam 5、patience 1.2、repetition penalty 1.08、previous text conditioning 關閉、temperature 0、VAD 900ms、padding 400ms、詞級時間開啟。Qwen 使用同一音訊的相同分段規劃、Chinese、無提示詞、BF16、SDPA、greedy、上限 1,024 tokens，全部切片未觸及 token 上限。

Qwen 與 Whisper 的提示及精度不同，因此跨模型差異包含整個設定，不能歸因於模型單獨效應。部分 GPU 實驗並行，執行秒數不作速度排名。前段 runner 尚未記錄程式雜湊；後續增加診斷欄位，不能宣稱全部輸出來自最後一版 runner。

原保留段本輪已參與調參，均明確標為探索資料，不再冒充未見驗收集。**參考稿尚未逐段人工回聽；沒有把 ASR 一致或插入差異當作音訊真值。**

## 結果一：單一參數不足以解決問題

以下為三段加總錯誤字數除以加總參考字數的原始 ASR CER，不是各段百分比的平均。

| 參數 | large-v3 | turbo |
|---|---:|---:|
| 控制組 | 31.51% | 28.80% |
| 重複懲罰 1.0 | 31.04% | 27.49% |
| 關閉 VAD | 30.50% | 27.10% |
| 關閉詞級時間 | 31.35% | 28.03% |
| 溫度重試 | 31.51% | 28.80% |

完整 large-v3 的讀誦段，控制組原始 CER 52.72%、刪除 83 字；完整分段後為 20.11%、刪除 2 字。此處相對下降約 61.86%，**比較對象是相同模型的原始 ASR 控制組，不能充作較舊流水線下降 40% 的驗收結果。** 關閉詞級時間仍有大量刪除與無效時間，無法把缺漏歸因於詞級時間單一因素。

## 結果二：分段與提示詞有交互影響

large-v3 分段開發段的原始 CER 升至 59.40%，出現「本講名相」、連續術語重複、替代字元及 Amara.org 字幕文字。相同分段取消提示詞後為 30.48%，風險旗標消失；仍需聽核才能確認所有文字。

Qwen 的開發段刪除差異為 20 字，少於 large-v3 控制組的 68 字，但插入差異為 118 字，多於其 53 字。讀誦段 Qwen 刪除差異為零、插入差異 23 字；未聽核前，不能斷言插入差異全是幻覺，也不能把較少刪除當作整體較正確。

## 結果三：接回校對流程仍未勝過原流水線

下表全部是校對後 CER；九組候選逐字輸出均通過正體與禁止同音錯字檢查。

| 切片 | 原流水線 | large-v3 分段＋提示 | large-v3 分段無提示 | Qwen 分段無提示 |
|---|---:|---:|---:|---:|
| 開發段 | 24.81% | 56.62% | 27.14% | 28.36% |
| 問答段 | 23.11% | 19.81% | 16.04% | 18.87% |
| 讀誦段 | 15.76% | 18.48% | 16.85% | 18.48% |
| 加權整體 | 23.24% | 45.17% | 23.86% | 25.41% |

本輪最佳問答候選較原流水線下降 30.61%，仍未達 40%。分段無提示的整體為 309／1,295 字錯誤，原基準為 301／1,295，整體仍退步約 2.66%。不挑選不同片段的最佳模型拼成虛構的路由器成績。

## 環境、重現與證據

GX10／GB10。Whisper：faster-whisper 1.2.1、CTranslate2 4.8.0，沿用第二輪唯讀模型掛載及無網路一次性容器。Qwen：`Qwen/Qwen3-ASR-1.7B-hf`，revision `bcd2b5b7f32b480ab5790554cfa8347f246a14f3`，Transformers 5.14.1、PyTorch 2.11.0+cu130；使用既有 `vllm/vllm-openai:v0.26.0-aarch64` 映像中的 PyTorch 做原生 HF 推論，**沒有啟動 vLLM 服務**。主機原 PyTorch 不支援 GB10，未改動它；音訊套件安裝在隔離 `/tmp` venv。

精確映像、權重、音檔、程式與輸出雜湊見同名機器報告 `2026-10-21-36A-round3-diagnostics.json`。原始結果、錯誤輸出、套件清單、網路受限的未校對嘗試與兩次成功校對的原始彙整均保存在沙盒，未以不佳結果覆蓋較佳結果或反之。

Whisper 容器需唯讀掛載整個 `scripts/` 或 runner 加上 `lib/asr_diagnostics.py`、`lib/pipeline_evaluation.py`；在第二輪命令上加 `--variant repeat_1`、`--partition silence` 或 `--prompt-mode none` 即可重跑對照。Qwen runner 需音訊目錄、既有控制組語音活動 JSON、本機模型目錄與輸出目錄，全部以 CLI 指定。

```bash
# 僅原始 ASR 診斷，不呼叫校對服務
python scripts/evaluate_asr_diagnostics.py --run-dir tmp/pipeline_v2/36A/round3

# 需先建立自己專用的 18001 → GX10:8001 tunnel
# 對全部分段候選實際執行校對；只在沙盒寫檔
VLLM_FALLBACK_URL=http://127.0.0.1:18001/v1/chat/completions \
python scripts/evaluate_asr_diagnostics.py \
  --run-dir tmp/pipeline_v2/36A/round3 --proofread
```

本輪九組校對分兩次執行；最終彙整以原始 ASR 雜湊及逐字輸出雜湊核對後合併，未重跑多次挑選較佳 LLM 回答。公開模型下載完成後，所有 GPU 推論容器均關閉網路。
