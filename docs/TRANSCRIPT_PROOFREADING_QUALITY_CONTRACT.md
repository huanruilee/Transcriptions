# 全庫逐字稿出版級校稿品質契約

> **流程優先順序與待閱校發布以 [最新版逐字稿流程](TRANSCRIPTION_WORKFLOW.md) 為準。** 本契約的「出版級完成」指人工確認層級，不阻止具清楚待閱校標示的機器處理稿先上線。模型候選仍須品質與來源稽核後才能發布，不能冒稱人工核定。

## 目標與界線

本契約將使用者提供的出版級《四法印》逐字稿與臺灣繁體中文用字規範，轉化為可重跑、可稽核、保守不改義的全庫校稿流程。模型輸出只能成為候選修改，不能直接成為正式逐字稿。

- `錯別字或常用字 2026.pdf`，SHA-256 `fc181dee415706d5ef05e11caf3de56a8593f1bc6660e8cec20e5b8abca5b439`

## 四層驗收

1. **結構完整性**：句子 ID、順序、時間戳、講者、段落及原始 digest 不得漂移。
2. **文字與用字**：臺灣繁體、標點、常用字和語法符合規範；多義用法不得全域盲目替換。
3. **音訊一致性**：同音詞、缺字、數字、引文、刪句與講者自我修正需有音訊證據。
4. **上下文與論義正確性（Doctrinal & Contextual Gate）**：
   - **滑動語境視窗（Context Window）**：校對單元必須依據前後 3 句以上（或 30～60 秒語意段落）之長程語境進行推論，禁止脫離上下文之單句盲目定字。
   - **佛理邏輯與專名實體消歧（Canon Entity & Semantic Resolution）**：經論著作（如《瑜伽師地論》、《法華經》、《空之探究》）、祖師法號、三乘名相（聲聞/獨覺/菩薩）、修行次第（聞思修、加行、資糧位）及法脈術語，字面通順但佛理顯然相違或文義不通者，必須依原典義理修正，不得保留荒謬同音錯字。
   - **邊界案例消歧典（Disambiguation Rules）**：一音多義之關鍵詞（如「自性/自信」、「資糧/資料」、「因緣/姻緣」、「自利/自立」）必須依據 `config/doctrinal-disambiguation-rules.json` 正反例條件嚴格判定，杜絕矯枉過正。

任一層未通過，都不得宣稱出版級完成。結構 PASS 不代表音訊或論義 PASS。

## 不可破壞條件與口語冗詞處理規範

- 原始 ASR 備份在候選階段保持不變，供時間軸與音訊回聽追溯。
- **不整篇改寫、必除口語冗詞、必合碎句並依語意補順**：
  - 禁止整段改寫、禁止改變法師原有的否定、數字、因果、宗義或立場。
  - **必須徹底清除無實義發語詞與口頭禪**（`呃`、`嗯`、`啊`、`喔`、`欸`、句首無實義的 `好，那`、`那，`、`好，`、`就是說，`、結巴重複 `這個這個`）。若單一 `sent-X` 整句僅含發語詞或冗詞，必須直接從 `sentences[]` 移除該句物件（禁止設為空字串 `""`）。
  - **必須合併被 ASR 切碎的單詞與子句**：同一詞語或同一連貫子句被切成多個 1～4 字短句（如 `傳，` + `達出去，`）時，必須合併為單一完整 `sent-X`（時間軸繼承 `start = 首句.start`、`end = 末句.end`），消除詞中碎逗號並依語意將句子補順。
- 內文與 `sent-X` 定稿後，`contentOverview` 四個 `evidence[]` 陣列與 `sourceDigest` 必須完整同步更新。

## 三級處理

### A. 確定性規則與碎句／冗詞整併

處理字形、標點、移除獨立發語詞句（`呃`、`嗯`、`啊`、`好，那`）並整併被切碎的 1～3 字子句（`consolidateFillersAndFragments`）。字形與標點規則列於 `config/transcript-proofreading-style-rules.json` 與 `scripts/lib/fluentPolishAudit.js`。

### B. 上下文消歧典與義理邊界判定

對於一音多義或易混淆之佛學關鍵詞，嚴禁無條件全域替換。系統讀取 `config/doctrinal-disambiguation-rules.json`，按語境特徵觸發對應的正向修正或反向保留（如「累積資糧」 vs 「講義資料」）。

### C. 本地／私有模型候選與兩階段審查（Two-Pass Review）

1. **Pass 1（義理消歧與依語意順句）**：以 500～800 字的長語境段落為單位，站在漢傳與藏傳佛學專家的角度，識別音近、文義不通與佛理相違之處，清除殘留口語贅詞並依語意將破碎短句順為自然通順的句子。
2. **Pass 2（保真與實義詞安全閘門）**：透過程式化安全閘門檢驗候選，確保未誤刪實義副詞、邏輯連詞與否定詞（如「剛好」「已經」「因為」「所以」「如果」「沒有」「不要」），且未進行無根據的整段改寫。
3. 候選產生優先順序為 **eNeural（`glm53-flash`）→ GX10 本地 vLLM（`nvidia/Qwen3.8-27B-NVFP4`）**，統一設定 `chat_template_kwargs: { enable_thinking: false }` 且單線程執行（`concurrency = 1`）。
4. 原典、課程詞庫和既有人工核定詞優先於模型直覺；疑似聽錯或幻覺區間須調用 GX10 Whisper 重聽原音確認。

### D. 低 Token 漏斗路由與頂級模型終審（Funnel Arbitration）

1. **漏斗過濾架構**：
   - 確定性規則、無爭議同音詞與碎句整併由管線直接處理；後續由主控 Agent 執行 **Stage 5 佛法專家逐段通讀審核**，同時驗收佛法名相正確性與文句流暢度（零 `呃/嗯/啊` 殘留）。
2. **終審 Prompt 範本**：
   ```markdown
   你是一位精通漢傳與藏傳佛學的權威校審仲裁者。
   【核心任務】
   審查語音辨識之「佛法名相誤植」與「文義顯然不通處」，清除口語發語詞並依語意補順破碎短句。
   【嚴格原則】
   1. 嚴禁整大篇改寫或無中生有；但必須清除無實義發語詞（呃、嗯、啊、好，那）並合併被切碎的詞句。
   2. 依上下文義理消歧（如：中觀空性作「自性」，世俗信心作「自信」）。
   3. 證據不足或無把握者，一律 REJECT（維持原文）。
   【本講背景實體】
   {{COURSE_MICRO_CONTEXT}}
   【待審爭議清單】
   {{DISPUTED_SNIPPETS_JSON}}
   【輸出格式】
   僅回傳標準 JSON 陣列：
   [{"id": "sent-xx", "action": "ACCEPT"|"REJECT"|"REVISE", "final": "修正文字", "code": "HOMOPHONE|DOCTRINE|FLUENT_SMOOTH"}]
   ```

### E. 音訊／人工覆核

以下類別不得自動核准：佛學名相、數字、否定詞、引文、人名、梵藏音譯、刪句、大幅縮短、語意補字、講者自我修正，以及任何模型低信心項目。

## 試點與全庫放行

1. 固定分層選取四門課各首、中、末三堂，共 12 堂。
2. 先產生候選 ledger 與覆核佇列，不改正式 session。
3. 程式化檢查 12/12 結構與 digest；Codex 抽查所有高風險修改；需要時回聽音訊。
4. 試點通過才分片處理全庫 302 堂；失敗的 session 隔離，不阻塞其他分片。
5. 全庫候選完成後，所有自動核准項目通過規則與冪等檢查，所有高風險項目保留人工決策狀態。
6. 正式套用、PR、合併與部署是後續獨立閘門。

## 可續跑與證據一致性

- checkpoint 綁定來源 digest、prompt 版本、endpoint、模型、穩定 runtime fingerprint、有效輸出上限與 batch size。
- 續跑前逐批重算 batch ID，重驗句數、proposal／uncertain 邊界與唯一性；不能只信任 batch index。
- 每堂同時只能有一個工作者；lock 記錄 PID、主機與時間，無存活程序的 stale lock 可安全回收。
- ledger、review queue、model responses 共用 `runId`，最後才寫入含三份 digest 的 completion manifest。沒有有效 manifest 不算完成。
- `pilot/` 與 `full/` 證據目錄分離。試點通過後，才使用 `--all` 進入 302 堂全庫候選生成。
