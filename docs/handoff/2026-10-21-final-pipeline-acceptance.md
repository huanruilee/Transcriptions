# 終稿穩定改善驗收規則

2026-10-21 使用者同意以 ASR 加 LLM 校正後的最終結果有穩定改善為目標，取代原交接文件「CER 相對下降至少 40%」的固定門檻。原始 ASR 只作診斷，無須每一階段均改善。歷史實測報告保留原當時門檻，不追溯改寫成通過。

## 操作定義

1. 比較最終逐字稿，使用相同音訊、人工聽核參考稿及相同文字正規化規則；基準與候選都須是完整 ASR 加校對流程。
2. 本輪採至少三段固定、未參與調參的音訊，涵蓋讀誦、問答與口語講解；三輪都比較舊版與新版。每輪切片集合、音訊雜湊、參考稿雜湊與參考字數必須一致。
3. 每輪以總錯誤字數除以總參考字數比較，候選均須嚴格下降；不要求固定下降幅度。單輪改善、打平或原始 ASR 改善，都不能獨自宣告穩定通過。
4. 必須有人工音訊真值、未見驗收集、原話保真核對與終稿品質檢查的證據。仍須保留所有實詞、重複與自我修正，只作使用者允許的同音校正、語氣詞清理、標點與講者標註；維持正體及禁止錯字檢查。
5. 三段三輪是目前的操作規則，不是統計顯著性保證。使用者未指定這個數量；它是將「穩定」落實為可測試門檻的實作選擇。每段結果及刪除／插入差異仍須公開，不得挑選每段最佳模型拼成未實作的路由器成績。

## 工具

`scripts/lib/pipeline_evaluation.py::compare_runs` 預設接受任何嚴格 CER 改善；如需重現舊門檻，可明確傳入 `minimum_relative_reduction=.4`。其 `target_met` 僅代表單次數值改善，**不代表穩定驗收或發布核准**。

`assess_final_stability` 驗證配對結果完整性、重複資料、雜湊一致性、三輪改善及內容核定狀態。它依據輸入的核定狀態判斷，不會自行聽音或認證核對者；每個狀態須附有可追查的實際審核紀錄。CLI：

```bash
python scripts/assess_final_pipeline.py --evidence path/to/evidence.json
```

證據包含 `stage: FINAL_VERBATIM`、`reference_audio_verified`、`unseen_evaluation_set`、`fidelity_checked`，以及 `runs` 陣列。每列包含 `repeat`、`clip`、共用的 `audio_sha256`／`reference_sha256`、`reference_chars`、`baseline_errors`、`candidate_errors`、`quality_passed`。共用雜湊指該次舊版／新版配對採用相同輸入，需由執行清單佐證，不能由核定旗標取代實際檔案驗證。

## 現有資料狀態

第三輪最佳較穩定設定的終稿整體 CER 為 23.86%，原流程為 23.24%。現有三段已用於調參，且只有單輪、參考稿仍待人工逐段聽核，因此新門檻下仍未通過。不得藉門檻變更把既有退步結果改稱成功。

後續以新未見音訊及聽核稿執行整體配對測試，再測多 ASR 候選、局部重辨識與受約束 LLM 校正。已發布 36A／36B 不覆寫，候選持續存入沙盒。正式預設及發布仍須等待內容驗收。
