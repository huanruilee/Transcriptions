# 逐字稿標準流程

版本：1.1。更新：2026-10-24（Asia/Taipei）。適用：所有課程及所有 Agent。
本文件合併至 `main` 後生效；後續一律讀取 [main 最新版](https://github.com/huanruilee/Transcriptions/blob/main/docs/TRANSCRIPTION_WORKFLOW.md)，不要複製一份自行維護。

## 1. 權威與適用順序

1. 使用者對本次任務的明確指示。
2. 本文件：產物分軌、保真、待閱校發布、驗證與交接流程。
3. [品質契約](TRANSCRIPT_PROOFREADING_QUALITY_CONTRACT.md)、[資料 Schema](DATA_SCHEMA.md)、[專案規格](SPECIFICATION.md) 等領域細節；涉及本流程的舊敘述以本文件為準，Schema 不得未經協調直接改動。
4. 舊 SOP、交接、skill 與歷史報告僅作背景和工具參考。Draft 文件／PR 不改變正式流程。

若現有程式、Schema 或文件尚未支援要求，明列缺口並採可稽核的人工步驟；不得宣稱已有自動強制攔截。不得以「測試全綠」代替音訊或論義已人工核定。

## 2. 先確認本次交付

開工先記錄 Task ID、講次、工作分支／隔離 checkout、來源 commit、來源檔 digest、允許的模型／provider、預期產物及發布範圍。保留別人的未提交內容。不直接改 main、不自動擴大全庫。

預設交付是**忠實原話閱讀版**。三種產物必須清楚區分：

| 產物 | 內容規則 | 來源與用途 |
| --- | --- | --- |
| 原始 ASR／原話來源 | 原樣保存；不以校字後文字覆蓋 | 追溯、還原、音訊對照 |
| 忠實原話閱讀版 | 校同音錯字、獨立嗯／啊／呃、標點及有證據的引號；保留全部實詞、重複、自我修正及問答 | 預設正文；可以待閱校上線 |
| 導讀／精煉講記 | 導讀明標 AI 摘要；精煉、刪贅詞或書面化須有另行授權，並與原話分開 | 學習輔助；不得當成原話或回寫逐字軌 |

檔案位置依課程既有 Schema 使用 `sessions/`、`verbatim/`、`publications/`、`source_outlines/`。不要假設所有課程都有相同格式。既有精煉 session 不得未審查就改成另一種資料結構。

## 3. 音訊與底本定位

先依 [參考資料與 Benchmark 規範](REFERENCE_EVIDENCE_PROTOCOL.md) 完成參考資料預檢，再開始本講轉寫／校字。必查影片說明欄與官方課程資料，尋找課本、既有逐字稿、經文、講義及勘誤；核對講者、講次、版本、頁碼／時間範圍並保存 inventory。找不到也記錄查找範圍與日期，不捏造底本、不無限搜尋。只讀過 repo 舊檔而未重新核對線上附件時，明示「既存副本、尚未核對線上版本」。底本、字幕及人工聽核稿的證據等級與使用角色不可混同。

- 核對官方索引／課程音訊映射及實際講次，記錄音訊 URL、content type、完整解碼時長與 hash。HTTP 200 本身不代表音訊可用。
- 音訊／完整模型回應放獲授權的工作區；本流程預設不提交完整音檔。若需提交短節錄，須另有明確範圍與來源證據，不能推論為一般授權。
- 依 `pageRange` 載入底本，也核對跨頁回看及下一講開頭。底本可支持核字與引文，不證明錄音中真的說過。
- 核對實際 model／runtime，不信端點別名或歷史效能數字。GX10 8010、8001、4001 及 tunnel 只是既有端點線索，當次使用必須檢查。外部 provider 必須有對應 payload 授權；連線失敗不得靜默外傳。

## 4. 生成候選與保真校字

1. 在隔離沙盒跑指定講次。`scripts/batch_convert_all.py` 是既有 ASR＋LLM 核心工具，但會寫 `courses/`；必須在候選 checkout 使用，不直接對正式來源全庫重跑。先查 `--help`，不要假設未合併分支參數可用。
2. 底本視窗及提示依講次建立；自然語意與停頓斷句，不恢復舊的 28 字硬切。prompt 回聲、異常重複或聲學缺口先標記，不憑模型判斷刪掉原話。
3. LLM 回應是候選。失敗／句數不符須有限重試，仍不符則保留原文並標記原因，不能靜默當成已校對。
4. 每項修改保存句子 ID／定位、before、after、理由、證據及來源 digest。保留 `rawText` 或獨立不可變來源；不修改原 ID、順序、時間、講者及非文字 metadata。既有工具若重編 ID／四捨五入時間，須保留原物件與映射，不能冒稱原物件未變。
5. 「對，對」及找詞、自我修正保留；不能刪除「啊難」字首來去語氣詞。數字、否定、宗義、難解名相或漏辨，沒有充分證據就保留原辨識並列待核。不能拿整段底本補成未辨識的原話。
6. 引號只包住有來源支持的實際讀誦片段；已讀片段不摘要替代，未讀片段不補寫。講者不能只靠「請問」等句型當成已識別；未知標待確認，保留原始標籤。
7. 已發布檔不作實驗輸出；36A／36B 基準檔尤其不得覆寫。36A 實驗指定 `tmp/pipeline_v2/36A/`。現有 CLI 的 `--out` 不等於安全保證，寫入前核對 resolve 後的目標。

`scripts/build_verbatim_track.py` 可協助產生逐字軌，但產物仍須比較句子覆蓋、邊界、講者與來源映射。`scripts/active_learning_manager.py` 的全庫同步不是日常校字的預設動作。

## 5. 導讀、講記與同步

導讀獨立標示為 AI 整理，引用當前正文 ID／digest，區分講者主張、他宗批評與學員提問。舊來源改動後舊摘要審查不得自動沿用。

有精煉講記授權時，使用 [講記 SOP](STUDY_GUIDE_CALIBRATION_SOP.md) 的格式細節；其中「去贅詞、書面化」只適用精煉軌。時間若依字數估算必須明示估算，不能宣稱聲學精確。

同步工具先輸出候選，正式同步需對新正文有效的摘要審查；不可只更新 digest 讓驗證通過。例如《入中論》既有工具：

```sh
# 將 SID 換成已指定講次；輸出目錄須為新目錄
python3 scripts/sync_study_guide_to_session.py SID --candidate-dir tmp/workflow/SID/candidate
# 在候選與新摘要審查均完成、獲准正式套用後，二擇一執行
python3 scripts/sync_study_guide_to_session.py SID --overview-file tmp/workflow/SID/reviewed-overview.json
```

`--candidate-dir` 與 `--overview-file` 不可混用。渲染時明列單一 Markdown 路徑，避免無參數批次重寫出版品。新科判需核對原典物理頁／行及當講截止點；不得因提到關鍵詞就掛到未講的後續科判。

## 6. 待閱校版可以先上線

使用者已同意：尚未人工完整校稿的成果可以先上線，之後在閱讀中校正。**人工逐句回聽不是待閱校發布的先決條件。** 發布仍需來源可追溯、自動品質通過、修改可檢查、獨立工程 review 及正常 CI／部署。

| 顯示狀態 | 可以宣稱 | 所需記錄 |
| --- | --- | --- |
| 待閱校版 | 已完成機器處理，尚未人工完整校訂 | 來源版本、生成日期、待核項目與自動驗證 |
| 閱校中 | 已開始閱讀，部分仍待確認 | 已確認範圍、修改紀錄、待回聽項目 |
| 已確認版 | 使用者明確確認的閱讀／聽核範圍 | 核定者、日期、對應版本與剩餘限制 |

這是發布語意，不要求立刻新增三個 Schema enum。沿用現有欄位及可顯示的說明；缺少欄位時用隨產物版本綁定的 manifest／說明保存。不能只在內部報告寫待核：**閱讀頁、獨立 HTML／Markdown 與實際下載都須讓讀者看見待閱校狀態**。若既有 UI／匯出尚無法顯示，先做小範圍功能修正，不能以未顯示的 metadata 宣稱完成。

可用標示：「待閱校版：經 ASR 與 AI 輔助整理，尚未人工完整校訂；疑義請配合原音核對。」未回聽不得填 `humanListened=true`。已閱校也不等於整講逐字聽核。

## 7. 閱讀校正與回歸資料

已有逐字稿可先作「文字參考基準」，但只有綁定相同錄音區間與來源版本、經人工聽核確認的部分，才能作「人工聽核 Benchmark」。是否聽核、是否參與提示／調整，以及評估模式必須分別記錄；已有逐字稿不自動成為 gold。參與開發的案例歸回歸集；盲測留出集須按講次／音源分組，禁止重疊片段洩漏。詳見 [Benchmark 分流與交接](REFERENCE_EVIDENCE_PROTOCOL.md#benchmark-分流)。使用同一參考稿輔助生成再比對它，只能報告 reference-assisted 結果，不稱獨立準確率。

每次人工修改保存來源版本、句子 ID、before／after、音訊區間、時間、修改者及理由；區分「閱讀確認」「音訊回聽確認」「底本核字」「純編輯」。目前未具備自動修訂紀錄的入口，以人工 ledger 補齊；本文件不宣稱後端功能已完成。

一次校正先適用本句，不直接推廣全庫。「長短→常斷」等需上下文的規則必須有正例與一般語境反例；檢查重複執行結果一致。人工修改可成為回歸候選，但開發案例不能稱作未見驗收集。原始 ASR、校字候選與發布修訂均可還原。

升級「已確認版」須由使用者明確確認範圍；未解決高風險疑點明列，不能以模型票數或使用者曾開啟頁面自動核定。

## 8. 驗證、提交與部署

迭代時跑相關測試；固定最終成果後執行：

```sh
npm run test:v2
npm test
npm run summaries:audit
node --test tests/acceptance/goldenStandard.test.js
npm run build:v2
```

另跑本課程所需來源／ledger 稽核；不修改 gate 或測試預期來掩蓋正文錯誤。發現歷史 skip 或門檻只掃部分 engine，報告範圍，不宣稱全庫皆驗證。公開文字要求繁體中文、零適用禁止同音錯字；原始辨識證據則保留原貌。新訂正規則不能因湊零禁字而誤改實詞。

瀏覽器確認閱讀頁、原話、導讀、待閱校標示、寬窄排版、下載完整性及末句音訊。獨立 reviewer 看固定 commit 與證據；工程 PASS、內容核定、發布與人工聽核分開記錄。

使用新分支。建立 PR 必須帶明列 base、head 及 body 檔，避免互動卡住：

```sh
gh pr create --base main --head codex/TASK-BRANCH --body-file /tmp/TASK-pr-body.md
# 確認本次已有合併授權，且固定版本 review／CI 通過後
gh pr merge PR_NUMBER --merge
```

禁止 squash、force-push。合併後核對同一 main SHA 的 CI／Pages 部署與實頁；有問題用新修正／revert PR。不能把 PR CI 綠燈寫成已部署。

## 9. 交接與版本維護

交接最少記錄：Task／講次、分支／commit、來源與成果 digest、已過 gate 及證據路徑、待閱校與待回聽範圍、執行中工作、下一條命令、禁止覆寫檔案與授權界線。不要在交接文件保存 token／憑證。

交接另附 reference inventory 路徑、每份資料的使用角色與版本核對狀態、Benchmark 的聽核／資料分組／參考暴露狀態。接手者先核對 digest 與缺口，不重做已通過且來源相符的工作。可直接採用 [參考資料交接範本](REFERENCE_EVIDENCE_PROTOCOL.md#交接範本)。

維護時修改本檔、更新版本與下表，並同步 `AGENTS.md`／`START_HERE.md` 的入口；舊文件保留歷史，但明示被取代之處。執行中任務綁定來源版本，新版出現時先看差異，不盲目重跑已完成工作。
