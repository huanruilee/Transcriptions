Official upstream issue https://github.com/actions/deploy-pages/issues/451 describes the same versions and same-job upload/finalization visibility race, and reports moving upload into an earlier job as a mitigation. Official guidance https://github.com/actions/deploy-pages/blob/main/README.md recommends a dedicated deployment job with needs:build. This is evidence for the mitigation, not proof of GitHub's internal root cause in our runs.

The change separates build/upload and deploy with needs:build. The successful-main-push acceptance condition stays on build, with a latest-default-branch SHA check; deploy cannot run unless build and exact-artifact browser validation succeed. Both jobs check out workflow_run.head_sha. Existing action pins, permissions, Pages deployment concurrency, exact-artifact tests and deployed desktop/mobile tests remain. The fresh deploy job restores Node/browser dependencies, downloads the github-pages artifact using the pinned official download action (digest mismatch fails), and extracts it into dist for exact live asset comparison; it does not rebuild the site. No transcript, date, source, model evidence, formal transcription workflow threshold or memory is changed.

Regression: githubGovernance now fails if upload and deploy share a job or deploy lacks its successful build prerequisite, exact-SHA checkout or live browser gate. RED on original workflow, GREEN7/7 after split. Live GitHub CI/Pages and formal55A checks remain required; local structural green alone is not publication proof.

Independent review found an ordering risk after splitting jobs: an old slow build could enter deploy after a newer one. The accepted/latest-main workflow gets a shared cancellation group spanning build and deploy; PR/failed/stale events get an isolated run-ID group and build skips stale head_sha != github.sha. GitHub documents workflow_run GITHUB_SHA as the latest default-branch commit: https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#workflow_run . This preserves invalid-event isolation while preventing reverse build completion from reviving an older release.
